# 12. UI

Tokens: amber = action needed (missing, unclear, needs_info, info_requested, pending_review); blue = ready (ready_for_review, auto_approved); green = done (met, verified, accepted, approved, not_required); gray = waiting (matching, checking, submitted, in_review). No red for any status. Body 14px, secondary 13px, titles 16px; weights 400 and 500.

## Admin (hidden from doctor navigation)

### A1. Policy library `/admin/policies`
Tabs: Benefit summaries, Clinical policies, Drug criteria. Columns: title, insurer, plan, year, role, source (Published with link, or Fictional banner), status, items, pending, FHIR valid. Upload dialog: file, role, source URL, download date.

Live ingestion steps: Validating, Reading pages, Cleaning (tokens before and after), Pre-check (role hint), Identity, Locating sections (tier used), Extracting group n of m, Grounding, Judging n of m, Building questions, FHIR, Saved as draft.

### A2. Policy page `/admin/policies/[id]`
- Header: identity with evidence and Edit; source link; status; Export audit; FHIR JSON viewer and Readable questionnaire.
- Routing panel: declared role, hint, format hints, cascade result (tier, failed tiers and reasons, page ranges, truncated flag), context stats.
- Review queue sorted by risk; each row: verdict badge, item summary, page, Accept, Edit, Reject; lock icon when edited; suggestion banner after reprocess.
- Item editor modal: left, source page with evidence highlighted; right, fields (text, type, codes, conditions, logic, values, page); original output collapsed; note; save re-runs checks and shows rebuilt questions.
- Question tree per rule: conditions, questions, types, enableWhen, pass condition in plain English, question verdict.
- Go live button, disabled with a reason until all items are decided, coverage is 100%, and FHIR is valid.
- Drug criteria: blocks table (drug, pages, status) with Extract and Go live per block.

### A3. Episode timeline
On every policy page and drug block: the episode list (sequence, actor, stage, status, summary, cache hit badge), filterable by stage, with links to the item or call it produced. Included in the audit export.

## Doctor

### D1. Order screen (Sambhav owns; this part supplies the catalog)
Patient (synthetic badge), insurer and plan from the catalog, service or drug from the catalog with search, free-text fallback, Order.

### D2. Match chooser
Shown when status is `matching`: candidates with matched phrases and pages; clinician picks one.

### D4. Answer forms
Reject: reason (min 5 chars). Enter: typed value, source picker (existing document or upload), evidence text, attestation. Inline validation errors; nothing submits until valid.

### D5. Packet preview
Header, every rule with answers, quotes, pages, verifier; attestations; attachments; provenance of the policy; FHIR response viewer; Submit to {insurer}. After submit, a status timeline.

## States

Every screen has loading skeletons, empty states ("No live policies yet. Upload one."), and errors with retry. Copy never says denied, rejected (for coverage), or not eligible. Dates as "Sep 2". Readiness always as fraction plus percent. Works at 375px; status is text as well as color; keyboard reachable.
